# Content strategy

## Identify what the page introduces

Start from the brief and corroborate details with the most direct public evidence. The README and product docs explain purpose, the quickstart or examples show how it is used, and public interfaces or source can resolve specific questions. Keep private configuration and internal implementation details out of the page.

Choose the type by what the audience is evaluating and what they should do next. When a repository hosts a SaaS product or agent skill, treat GitHub as a source and possible CTA destination. Use the repository direction when the project itself is what readers should evaluate, use, or contribute to.

| Page type | Signals | What to highlight first | Useful CTA when supported |
| --- | --- | --- | --- |
| Agent skill | A skill name, trigger conditions, agent instructions, and a defined workflow or output | The task that should trigger the skill, the output the user gets, and a real prompt or short input-to-output example | Install the skill, try a prompt, or read usage |
| SaaS | Users come to accomplish an ongoing task through a hosted product | The problem and outcome, then the product workflow or a real view that makes the outcome concrete | Try the product, view a demo, or sign up |
| GitHub repository | Developers evaluate a library, tool, template, or open-source project to adopt or contribute to | What the project solves, the most relevant capabilities, and the first working example or quickstart | Open the quickstart, view the repository, or see contribution instructions |

For other offerings such as a course, gym, or sports program, name the type from the brief. Identify who the page serves, what they need to decide, and what evidence will help them take the next step. Use those answers to choose the sections.

## Select the hero and highlights

1. Write a one-sentence hero message that tells the intended reader what the offering does and why it matters to them. Use terms that would still make sense to someone who has never seen the brand.
2. Choose one to three supporting highlights. Rank them by how much they help the reader decide whether to take the primary action. For each, note the concrete capability or outcome, its source, and how to show it, such as a prompt and result, a screenshot, or a quickstart command.
3. Put the strongest message in the hero and the strongest evidence early on the page. Use later sections for distinct questions the reader still needs answered, such as how the product works, what it requires, or where to find docs. Keep the sections the user requested and skip generic sections that repeat the hero.

Use evidence for capabilities, prices, plans, testimonials, metrics, guarantees, and links. Omit optional proof and commercial details when they lack support. Resolve gaps that affect an essential claim in chat.

## Choose one primary action

Use a CTA label that describes its real destination or action. Link to the destination supplied in the brief or documented in the source. A useful in-page section, such as a real quickstart, can serve as the destination when it fulfills the same goal. If the primary action needs an unavailable destination and no in-page section can fulfill it, ask for the destination before building.

Repeat the same primary action where it helps the reader. Use secondary links for exploration, such as docs alongside an install CTA. Skip empty links and controls that imply a submission or purchase the page cannot perform.

For additional guidance on arranging value propositions, visuals, and evidence, see [Unbounce's anatomy of a landing page](https://unbounce.com/landing-page-articles/the-anatomy-of-a-landing-page/).
